# 取证录像回放说明（Jetson Xavier NX）

## 1. 录像文件位置与格式

| 项目 | 说明 |
|------|------|
| 默认目录 | `/home/lcfc/evidence`（配置项 `[record] save_path`） |
| 文件命名 | `record_<码流通道>_<yyyyMMdd_hhmmss>.mp4`（旧版本无通道号） |
| 编码 | H.265 / HEVC，`-c:v copy` 直拷码流，25 fps |
| 分辨率 | 跟随所选码流：主码流 `3840x2160`(101) / 第三码流 `1920x1080`(103) / 子码流 `704x576`(102) |

## 2. 实测性能（2026-09-20，本机实测）

| 回放方式 | 1080p H.265 | 4K H.265 | 结论 |
|----------|------------|----------|------|
| 纯软件解码（CPU） | 约 32 fps | 约 **11 fps** | 4K 卡顿，不可用 |
| `ffmpeg -c:v hevc_v4l2m2m` | 初始化失败 | 初始化失败 | 报 `Could not find a valid device` |
| `mpv --hwdec=v4l2m2m` | 初始化失败 | 初始化失败 | 报 `No hardware decoding available` |
| **GStreamer NVDEC**（`nvv4l2decoder`） | 流畅 | **约 63 fps，流畅** | ✅ 推荐 |

根因：本机 NVDEC 只暴露字符设备 `/dev/nvhost-nvdec`，**不存在 `/dev/video*`**，
因此依赖 V4L2 M2M 设备节点的 `mpv` / `ffmpeg` 无法启用硬解，只能退化为软件解码。

## 3. 推荐回放方式

### 3.1 4K 录像：NVDEC 硬解脚本（推荐）

```bash
/home/lcfc/evidence/play_record.sh                 # 播放目录中最新的一个 mp4
/home/lcfc/evidence/play_record.sh 录像文件.mp4     # 播放指定文件
/home/lcfc/evidence/play_record.sh /home/lcfc/evidence   # 目录内全部录像依次播放
```

脚本源码位于项目内 `scripts/play_record.sh`。

管线：`filesrc ! qtdemux ! h265parse ! nvv4l2decoder ! nv3dsink`
（解码与显示全程在 GPU 内完成，零 CPU 拷贝）

> 注意：不要在 `nvv4l2decoder` 与 `nv3dsink` 之间插入 `nvvidconv`，
> 实测会报 `buffer format not supported` 导致无法显示。

### 3.2 1080p 录像 / 日常查看：mpv 与 celluloid

已安装：

| 软件 | 用途 |
|------|------|
| `mpv` 0.32 | 命令行播放器，快捷键丰富，适合逐帧核查、截图 |
| `celluloid` 0.18 | mpv 的图形前端，可在文件管理器中双击 mp4 打开 |

```bash
mpv /home/lcfc/evidence/record_20260918_162411.mp4
```

常用快捷键：`空格`暂停 · `←/→` 快退/快进 5 秒 · `↑/↓` 快进/快退 60 秒 · `,/.` 逐帧 · `s` 截图 · `f` 全屏 · `q` 退出

mpv 配置位于 `/home/lcfc/.config/mpv/mpv.conf`：截图自动保存到 `/home/lcfc/evidence`，退出后记忆播放位置。

### 3.3 为何未选 VLC

`vlc` 在本机同样无法使用 NVDEC（与 mpv 相同原因），4K H.265 播放会明显掉帧；
且安装体积与依赖远大于 mpv。因此仅安装 `mpv + celluloid`，4K 场景使用 NVDEC 脚本。
